## Architecture and Required Behavior

- UI: `MainActivity` creates `SpoofAppState`; `SpoofMyDeviceApp` selects default Miuix or Material. Both share Home, Profiles, Apps, and Settings. Dedicated activities handle editing, assignment, Safe Mode, diagnostics, and real-device information. `AppProfileSession` caches profile state across activities.
- Storage: `AppProfileStore` persists version-1 `app_profiles.json` containing `profiles`, `assignments`, and `globalProperties`; at least one profile is required. `ConfigFileManager` renders profile properties with preset/custom-mode metadata and migrates legacy configuration. Deleting a profile removes its assignments/default selection. Complete state is exported to preferences and best-effort shared temporary storage; saves broadcast `CONFIG_CHANGED`.
- Resolution: explicit app assignment overrides the optional default profile; neither means real values. `ProfileConfigResolver` prefers complete `json_state` over stale individual preference entries. `ConfigProvider.get_state` exposes complete state. Failed/unavailable transport returns `null` and retains the last valid immutable snapshot; valid unassignment clears spoofing and restores captured Build fields.
- Transport/startup: a lazy, single worker reads XSharedPreferences, direct files, then ContentProvider. Direct-file reads are capped at 4 MiB; readable private state precedes the temporary export. Package-load callbacks register lifecycle hooks without starting configuration transport. Validated application creation/attach can wait at most 100 ms for a direct-file-only startup cache, publishing lightweight identity before virtual-file preparation. Live reloads prepare complete views before publication; reload requests are coalesced and receiver-registration failure is retryable.
- Safety: `MainHook` implements `IXposedHookLoadPackage`, not Zygote initialization. Every entry, including companion activation, requires the primary application, matching context, eligible UID/package/flags, and fresh original `sys.boot_completed=1` plus `init.svc.bootanim=stopped`. Reject system/isolated UIDs, system apps, framework/System UI, launchers, input methods, root managers, and other protected packages. Boot/power-state properties are never spoofed. Capture Build originals before property hooks; apply them after other hooks are ready and restore on unassignment.
- SDK: active SDK properties are capped at the physical API; saved requests remain unchanged. Safe Mode additionally preserves real Android-version metadata for selected packages. `RuntimeSdkScope` uses short reference-counted transitions for overlapping Chromium/WebView and supported ShadowHook/ByteHook initializer calls, without holding a lock across runtime bodies. Restore the app SDK after the final lease and coordinate Java/native version bypass. Scope only recognized initializers, including R8-renamed synchronized wrappers; exclude getters and ordinary app methods. Matching SDKs avoid broad runtime hooks, installed guards become idle when no longer needed, and WebSettings callbacks are deduplicated.
- Identity: immutable `HardwareIdentity` and `ScopedHardwareRuntime` share aliases, CPU topology/frequency/MIDR, RAM/DDR, kernel, inventories/sensors, network, storage, and graphics values across supported readers. Java/native path indexes normalize POSIX paths, use depth-bounded ancestor lookups and compact inventories, and preserve exact proc-file/exception mappings. Ordinary absolute native app/font/database paths bypass snapshot locks and lookup allocations. Cache format 2 is part of the generation digest; completed generations are reused, partially evicted files restored, and writes/completion markers replaced atomically outside exposed inventories. Preparation failure clears the virtual view.
- Native: eligible ARM64/ARMv7 processes use the existing ShadowHook backend; x86/x86_64 use stubs/Java fallback. Guard against tracing reentry before state/lock access and bypass forked children. Keep real bionic `prop_info` handles and callback serials; never fabricate handles or hook the serial/seqlock. Allow legitimate nested client callback reads. Preserve driver/ABI selection values for recognized platform callers.
- Native compatibility: `NativeRuntimeConflictPolicy` probes host ShadowHook metadata without class initialization and compares its owner with the module loader. A separate or incomplete host runtime skips direct native installation; module-owned delegation and absent/bootstrap loaders retain native support. This prevents independent engines patching the same linker. Java/shell spoofing remains active, but raw native reads can retain physical values in these applications. Do not classify an app's native-library loader as a Chromium Handler loader.
- Subprocesses: `RewritingProcess` rewrites stdout incrementally with a 64 KiB line bound and preserves real stdin, stderr, exit/wait/cancellation behavior. `InteractiveShellProcess`, `ShellIdentityCommand`, and literal-quoted scripts support recognized readonly commands, options, multiple files, trailing slashes, `cd`/globs, persistent shells, and resets after profile changes. Emit each configured dump alias once; unsupported direct commands and control/write operations retain original behavior.
- Presets/settings: `DevicePresetCatalog` prepends a current-device preset, caches remote data in `remote_device_presets.json`, and accepts repository-root JSON, `presets/`, or direct directory sources. Default source is the project GitHub repository; HTTP connect/read timeouts are 8/12 seconds with cache fallback. Profiles preserve validated string-valued `hardwareProperties` in hardware/kernel/sensor/network/extended-CPU namespaces. Five locales are registered: English, Vietnamese, Korean, Japanese, and Simplified Chinese.
